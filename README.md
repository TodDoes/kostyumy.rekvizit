# Костюмы Реквизит

Бэкенд информационно-справочной C2C-платформы театрального реквизита. Приложение предоставляет REST API и отдаёт переданную HTML/CSS-вёрстку по адресу `http://localhost:8000`.

## Запуск

1. Скопируйте `.env.example` в `.env` и замените `JWT_SECRET` на длинное случайное значение.
2. Выполните `docker compose up --build`.
3. Откройте `http://localhost:8000/docs` для интерактивной документации API.

PostgreSQL доступен на `localhost:5432`, приложение — на `localhost:8000`. При первом запуске таблицы создаются автоматически.

Для запуска без Docker установите зависимости из `requirements.txt`, задайте `DATABASE_URL` и выполните:

```powershell
uvicorn app.main:app --reload
```

## Миграция и демонстрационные данные

Новая установка создаёт таблицы автоматически. Для уже существующей PostgreSQL-базы один раз примените SQL-миграцию:

```powershell
Get-Content migrations/001_required_item_specs_and_messages.sql | docker compose exec -T db psql -U costumes -d costumes
```

Она добавляет обязательные `color` и `measurements`, ограничения на заполнение всех характеристик, составные индексы для фильтров и таблицу сообщений. После запуска приложения заполните локальную базу демонстрационными данными:

```powershell
docker compose exec api python -m app.seed
```

Сидер идемпотентен: если карточки уже существуют, он не изменяет базу. Он создаёт 15 разноплановых предметов с Unsplash-фотографиями; учётные данные администратора для локальной демонстрации выводятся в консоль запуска сидера.

## Основные сценарии API

- `POST /api/auth/register`, `POST /api/auth/login`, `GET /api/me` — учётные записи и JWT-авторизация. Пароли хэшируются Argon2; после пяти неверных попыток вход блокируется на 15 минут.
- `GET /api/items` — публичный каталог с одновременными фильтрами `q`, `category`, `color`, `material`, `size`, `measurements`, `style`, `condition`, `transfer_type` и постраничной выдачей 12–20 карточек.
- `POST /api/items`, `POST /api/items/{id}/photos`, `POST /api/items/{id}/publish` — черновик карточки, загрузка до 8 JPG/PNG/WebP-фотографий по 10 МБ и отправка на модерацию. Для карточки обязательны название, категория, цвет, материал, размер, мерки, стиль, состояние, тип сделки и цена. Заголовок `Idempotency-Key` предотвращает дубли при повторной отправке.
- `GET /api/items/{id}/qr?format=svg|png` — постоянный QR-код карточки. `GET /api/items/{id}/history` возвращает только добавляемую историю.
- `PUT|DELETE /api/items/{id}/favorite`, `GET /api/me/favorites` — избранное.
- `POST /api/items/{id}/requests`, `GET /api/me/requests`, `PATCH /api/requests/{id}/status` — заявки. Допустимые переходы: новая → обсуждение → согласована → завершена, с отменой до завершения; согласовать и завершить может владелец изделия.
- `GET|POST /api/requests/{id}/messages` — переписка участников сделки; первое сообщение переводит новую заявку в обсуждение.
- `GET /api/admin/items/pending`, `PATCH /api/admin/items/{id}/moderation` и `GET /api/admin/reports/deals.csv` — очередь модерации, решение модератора и CSV-отчёт.

Все защищённые методы принимают `Authorization: Bearer <JWT>`. Роль администратора хранится в базе; её следует назначать через администрирование базы до появления отдельного интерфейса управления ролями.

## Соответствие ТЗ

В модели есть роли, объявления со статусами, отдельное файловое хранилище фото, поиск с индексами, неизменяемые журналы действий и истории изделий, QR-коды с постоянным `public_id`, избранное, чат и сделки с проверкой прав/переходов и административный аудит. Интерфейс использует Fetch API, а не моковые данные: работает с каталогом, формой объявления, избранным, заявками, чатом и очередью модерации. Docker Compose поднимает PostgreSQL отдельно от API; секреты и URL базы не фиксируются в репозитории.
